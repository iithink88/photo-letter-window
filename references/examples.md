# 案例库 · 槽位怎么填

## 一、五个原作案例反推（CATS / RUN / BREW / ACE / LENS）

原作者用同一套提示词跑了五个主体，这五张覆盖了全部典型情况，先照着它们对齐直觉。

| | CATS | RUN | BREW | ACE | LENS |
|---|---|---|---|---|---|
| 主体 | 两只猫趴石台 | 女跑者跨步 | 手冲壶+滤杯 | 女球员挥拍 | 老胶片相机 |
| 词 / 字数 | CATS / 4 | RUN / 3 | BREW / 4 | ACE / 3 | LENS / 4 |
| 底色 | 深棕 `#3A2E28` | 米白 `#EDE6D6` | 深墨绿 `#2C4034` | 宝蓝 `#2A5FA8` | 暗红 `#6E1418` |
| 强调色 | 橙黄 | 橙 | 米白 | 亮黄 | 米白 |
| 手写标语 | Sunny Days（右上） | Keep Going（左上） | Slow Mornings（右上） | Game On（右下） | Shoot Film（右上） |
| 底部小字 | 无 | SAME STEPS / BRIGHTER DAYS｜FURTHER · STRONGER · HAPPIER. | COFFEE / RITUAL / FOCUS | TENNIS / DISCIPLINE / LIFE｜MORE THAN A SPORT. IT'S A MINDSET. | ANALOG / PATIENCE / GRAIN｜36 FRAMES PER STORY |
| 突破元素 | 猫爪垂到照片带下方 | 腿与鞋越过带底 | 壶嘴越过带左 | 球拍与球越出 | 背带越出带左 |
| 手绘装饰 | 太阳涂鸦 + 猫爪印 | 橙色斜箭头 | 白色大椭圆环 | 黄色球轨曲线 | 光圈图标 |

> **看这五张先记住一件事**：下半部分的照片是**一整条横贯画面的带子**，词用实心深色压在带上。所以字与字之间、字腔里（C/A/R/P 的孔洞）都是照片，照片在带子上是连续的。不是「字母镂空、字里透照片」——那种做法字间会露出一块块纯色底，画面立刻断掉。

**五条可迁移的规律**：

1. 词一定是 3-4 个字母，且都是**画面主题的名词或动作**，不是形容词。
2. 底色决定气质：深棕=温暖怀旧，墨绿=沉静高级，宝蓝=运动清爽，暗红=质感匠气，米白=明亮年轻。
3. 手写标语全是**两个词**，其中一个是动词（Keep Going / Shoot Film / Game On）。
4. 底部小字右侧那句永远是**关于生活的短句**，不是产品描述（"36 FRAMES PER STORY"而不是"35mm film camera"）。
5. 每张都有且仅有一条手绘线/环/箭头，用来打破呆板的基线。

## 五、单变量调参法

一次只动一个旋钮，否则不知道是谁起的作用：

1. **先定词**（3-4 字母，不再改）
2. **再定底色**（`suggest_bg_dark` 与 `suggest_bg_paper` 各试一张，选气质对的）
3. **看字母窗内容**——里面是主体吗？能认出完整的主体吗？认不出就调 `--window-fill`（0.95 → 0.9 → 0.8，越小越宽松），或回去裁图
4. **调大小**（`--word-width` 0.92 → 0.96 → 1.0，选最满不出戏的）
5. **加装饰**（标语 → 底部小字 → 手绘线，一次加一段，看是否过载）
6. **压边**（`--bite` 0.03 → 0.05 → 0.07）

每改一次存一个新文件，别覆盖。五轮以内一定能出片。

## 七、猫躺石台（"字母里看不到主体"的完整修复过程）

一张 531×355 的猫图：两只猫趴在石台上，猫占画面上 57%，下面是石台和草地。第一次出片，字母 CATS 里透出来的是**猫头顶一截毛 + 整块石台 + 草地**，主体几乎看不见。

按顺序做了三件事，缺一件都好不了：

| 动作 | 具体做法 | 效果 |
|---|---|---|
| ① 按主体缩放 | 量抠图 alpha 的 bbox，反推 zoom 让主体铺满字形（`--window-fill 0.95` → zoom 1.39） | 猫的脸和身体进窗了 |
| ② 切掉地面 | bbox 底边里装的主体质量不足 10% 就切掉，顶边不动 | 石台从窗前退出去了 |
| ③ 关掉宽溢出 | 溢出侧接触面宽度 > 字宽 72% → 不是"部件"是"整条边"，收回字母内 | 字母下方那根横贯画面的照片带消失 |

**教训**：`--window-zoom` 只解决"取景位置"，解决不了"取景尺度"。主体占画面不到七成时，光平移镜头没用，必须按 bbox 反推缩放——这就是 `_fit_subject()` 和 `_tight_bbox()` 存在的原因。

三次尝试的顺序与症状（过程图已清理，只留最终样张 `样张_猫CATS_探出.jpg`）：
- 只调位置 → 字母里是石头 + 草地（主体看不见）
- 加了切边但顶边也切 → 只剩一撮毛，认不出猫（耳朵质量太轻被当虚边切掉）
- 缩放 + 只切底/侧 + 关宽溢出 → 橘猫身体和白猫侧脸在字母里，无照片带 ✅

## 八、字里到底该有画面还是实心墨（两次读反层级）

用户在第五、六轮连续报了两个相反的错，值得记下来：

| 用户说 | 我的理解 | 改了什么 | 结果 |
|---|---|---|---|
| "字母里的画和字母间也充满了猫，保持画面整体连贯" | 照片要铺成一条横贯画面的带子，字间也是照片 | 加 `--mode band`：照片按「画布宽×字高」铺满整条带 | 对了 |
| "是文字里有画面，不是文字是黑色的" | 字的笔画里不能是纯墨 | `--veil 0.55`：字=同一张照片压暗 | 对了，但暗照片上高光冲掉轮廓 |

**中间试过的四种做法**（对照图 `对照_四种做法.jpg`）：

| | 字内 | 字间 | 判断 |
|---|---|---|---|
| A `--mode window` | 照片 | 纯底色 | 字间断开，已被否 |
| B `--veil 1.0` | 实心墨 | 照片 | 参考图的样子，字里没画面，已被否 |
| C `--veil 0.55` | 压暗的照片 | 照片 | **当前默认** |
| D `--key light` | 原亮度照片 | 压暗 | 亮照片（草莓）上字读不出来 |

**C 的两个坑**，都是量出来的：

1. 纯乘 0.45：照片高光（草莓的籽 238 → 107）压完仍比字间（89）亮，字的边缘被冲开。实测对比只有 1.83 倍。
2. 只加软限幅（天花板 61）：轮廓立住了，但颜色一起被压没了，猫毛的橙和石头的灰分不开，字看着还是"匀的一块深色"。

最终做法：**只压明度、保色相饱和度 → 软限幅（天花板=带均亮度×0.62）→ 带内对比拉 1.85 倍 → 饱和度补 1.5 倍**。猫图实测字内 39、字间 122、对比 3.1 倍，字内还有 ±14 的明暗起伏。

**教训**：这个效果的层次关系是「照片在最下面，字是压在照片上的一层深色玻璃」。玻璃得是半透的，但不能透到让字的边缘消失——上限必须由字间的亮度反推，不能凭感觉给个系数。

## 第九节 · 参考图其实是「字里是照片」，而我错了七轮

用户七次说"你仔细看图"，我七次交出"深色字压在照片带上"。第八轮才用代码把这张图拆开。

**决定性的一次测量**：把参考图的暗部按主色聚类。

```
色 (40, 32, 24)  占 22.49%      ← 一个桶就吃掉近四分之一
底色占比 28.6%
底色连通块：4 个
  块1  21.9%  bbox x[2,1095] y[2,564]   ← 铺满整张画布的一整块
  块5   1.9%  bbox x[129,278] y[133,294]  宽高比 0.93  ← C 的内腔
  块4   1.7%  bbox x[739,905] y[13,224]   宽高比 0.79  ← 另一个字腔
  块11  1.2%  bbox x[2,197]   y[411,564]
```

关键不是"暗占 28%"，而是**暗只有 4 个连通块，最大那块横跨整张画布**。如果字是黑色实心块，暗会分成 C / A / T / S 四块大的独立区域。现在只有"围绕字母的一整片"加三个"被字母包住的小孔"——这就是标准的**字里是照片、字外是纯色**。

**为什么眼睛会骗人**：字母够粗时，深色的字腔（C 的碗、A 的三角、S 的两个口）本身就长得像笔画，"照片当字、深色当底"会被读成"深色当字、照片当底"。参考图尺寸只有 1098 宽，缩到手机屏上看，两种读法几乎无法区分。

**三次被同一个错觉骗到**，每次都是量了才醒：

| 现象 | 我的误判 | 真相 |
|---|---|---|
| 字顶外多出两条斜亮笔画 | 溢出层漏光 | 是 `--line` 手绘曲线的残段，字根本没溢出 |
| 三张样张看着像"纯色字+照片底" | 版面做反了 | numpy 统计掩码内外均色，字内 146 / 字外 50 |
| `_wcmp` 三档加粗看着字是黑的 | 字重不够 | 字形遮罩白占比 35.6%，字是照片，只是**太细** |

**教训**：
1. **判极性别用眼睛，用连通域数量。** 暗区如果只有 1 个大块横跨画布，那暗就是底。
2. **加粗之前先确认方向。** 字太细会让深色字腔吃掉画面一半，正确方向也会被读反；但把方向错的图加粗一百遍也没用。
3. **交付前裁一个字母放大看。** 这是唯一不骗人的检查方式：A 的两条斜腿是毛 = 对，三角内腔是深色 = 对。

**这一轮真正改掉的代码问题**（不是调参）：

| 症状 | 根因 | 修法 |
|---|---|---|
| 字只占中间一条，上下两大块空 | 3:4 竖版装不下四个满高字母 | glyph 默认画布改横构图 1536×768；`--split` 默认 0（不再有上横条） |
| 字母糊成一团团块 | Georgia Bold 靠 `MaxFilter` 硬吹 | 新增 `GLYPH_FONTS`，glyph 默认 Arial Black；加粗改成按字号比例（`--weight-pct`） |
| 判定永远返回 None，从没探出过 | 门槛写成 `prom × depth` = 0.3×0.42×字高 ≈ 150px | 门槛改成按字高的绝对比例（3%），`spill` 与门槛彻底解耦 |
| A 字下方"凸出 500px"的假阳性 | 基准线用了"每列字形最低点"，A 底部缺口把基准拉高 | 基准线改成字形外接框的那条边 |
| 探出的是一条 300px 宽的横带 | 逐列判定认得出"比边更凸"，认不出"段太长" | 加连续段过滤：段长 > 字宽 18% 砍掉，段均深度还要比中位数深 1.55 倍 |
| 照片发灰、没劲 | 做旧只提亮不提对比 | `_print_treat` 加 S 形对比 + 暖偏（红 +5 / 蓝 -4） |
| 标语被上边缘裁掉六成 | glyph 没有分界线，还按 `(split_y+top_y)/2` 放 | glyph 单独给 `max(H*0.030, top_y*0.55)` |

### 试错记：三次都错在同一件事上

| 试法 | 表面症状 | 真因 |
|---|---|---|
| Arial Black + `--weight-pct 0.026` | 字腔糊死、连成一片 | 整体吹胖，横竖一起粗 |
| Impact + `--squeeze 0.88` | 字腔太小、字距太挤 | 字体本身字腔就窄，不是参考那一挂 |
| Arial Black + `--squeeze 0.55` | 字母"竖细横粗"，像被压扁 | **横向压缩把竖笔画压细 45%，横笔画不动** |

最后一版的解法：**`--squeeze 0.55` 压出正确的宽高比，再用 `--fat-x 0.022` 把横向补回去**。压缩是各向异性的，补偿也必须是各向异性的——这一条是整轮最值钱的结论。

## 十一、按「照片覆盖率」校准版面（第九轮）

拿到完整参考图之后，光靠眼睛说"差不多了"是不行的——四轮里我一直觉得"已经很接近"，一量就露馅。**方法：把参考图和成片都做同一组统计，逐个数字对。**

统计脚本（不依赖任何外部库，只有 PIL + numpy + scipy）：

```python
a = np.asarray(Image.open(p).convert("RGB")).astype(np.float32)
bg = np.median(a[-4:].reshape(-1, 3), axis=0)          # 底边四行当底色
m = np.abs(a - bg).sum(axis=2) > 45                     # 离底色的像素 = 照片
ys, xs = np.where(m)
# 覆盖率、字带上下界、笔画宽度（距离变换 ×2）
dt = distance_transform_edt(m)
```

### 量出来的差距（参考 vs 改之前）

| 指标 | 参考 | 改之前 | 改之后 |
|---|---|---|---|
| 照片覆盖率 | 44–45% | **33.2%** | 40.9% |
| 字带（含渗出） | y 0.195–0.800 | y 0.209–0.863 | y 0.209–0.824 |
| 笔画宽度 | 0.067H | 0.060H | 0.062H |
| 字缝宽（中段） | 0.019–0.088W | **0.092 / 0.199 / 0.143W** | 0.02–0.06W |
| 照片亮度 mean / p10 / p90 | 163 / 99 / 212 | 148 / 84 / 202 | 156 / 93 / 204 |

三个数字直接指认了病灶：**覆盖率低 11 个点、字缝宽 5–10 倍。**

### 试错记：三刀，每刀都对了一半

| 试法 | 表面数字 | 实际发生了什么 |
|---|---|---|
| `--tracking 0.09 → 0.02`（以为"收紧字距就有缝感"） | 覆盖率 35.4%，反而更低 | 字距收紧后**字整体变小**（宽度是定死的），字缝确实细了，字也没长大。真正缺的是**字宽**，不是字距 |
| `--fat-x 0.030 → 0.042` | 覆盖率 **43.6%**，几乎命中 | 数字达标，**A 的三角被横向挤成一条缝、C 的碗基本堵死**。放大裁一个字母立刻看穿——又一次败在"只看整体缩略图" |
| 最终 `--word-width 0.96 + --tracking 0.03 + --fat-x 0.030 + --bottom-pad 0.165` | 40.9% | 字宽够了，字缝是字挤出来的，字腔还开着。**覆盖率不是目标，是字够宽之后的副产品** |

> 结论一句话：**字缝要靠字够宽自己挤出来，不能靠加字距**。加字距只会把字挤小，缝反而更明显。

### 叶片轮廓：矩形膨胀的必然结果

`_profile_zone` 放行某几列之后，凸出部分的外沿是 `_dilate(region, R)` 的边界——**矩形膨胀的边界就是矩形**。所以探出来的永远是一块方角方边的"贴纸"（第一版在字母下方留下了 80×86px 的方块，和一根本不该存在的竖细丝）。

解法是在连续段内按正弦收口：

```python
taper = math.sin(math.pi * (xx - s + 0.5) / ln) ** 0.55
reach = min(int(d[xx]), max(1, int(round(depth * taper))))
```

两端收到 0（和字形边贴回去），中间最深（受该列实测深度约束）。轮廓自带弧度，才像爪子或耳朵；再 `GaussianBlur(1.2)` 留一层柔边，否则照片上会有一道刀切线。只有 1–2 列宽的段（一根飘起来的毛）= 悬空细丝，直接丢。

### 字形边缘做旧（`_wear_edge`）

做完照片做旧，字边还是矢量级的干净——一眼现代软件排的。参考图的字边是**毛的**：缺墨、溢墨、宽窄不一。

做法是把字形当成一条等高线，用噪声去推它：`signed = 内部距离 - 外部距离`，`th = (noise - 0.5) * 2 * amount`，保留 `signed + th > 0`。噪声 = 4px 低频块（0.55）+ 逐像素高频（0.45）——只用低频会成均匀波浪，只用高频会成砂纸。

| 幅度 | 效果 |
|---|---|
| 0.007 × 字高（≈4px @1440） | 像印歪的丝网版，字还立得住 |
| 0.010 × 字高（≈6px） | 开始像虫蛀，字腔边缘出现缺口 |
| 0.016 × 字高（≈10px） | 直接是破纸，别用 |

**磨损必须作用在字形轮廓上，不能只作用在照片上**——只做照片，字边还是那条完美曲线，等于白做。

### 影调：旧印片没有纯黑

参考图的照片 p10 = 99（我们的 84）。差的不是"亮度"，是**黑位**。乘系数 + lift 只抬中间调，暗部还是黑的，一眼是屏幕里的照片。

正确做法是先抬黑位再提亮：

```python
bp = 47 * a                                       # 黑位抬到 35 左右
k  = 1.0 + 0.10 * a
lift = 8 * a
out = im.point(lambda v: min(255, int(bp + v * (1.0 - bp / 255.0) * k + lift)))
```

配套把去饱和从 0.16 降到 0.08（抬黑位本身已经把颜色压灰了，再叠 0.16 会发土），S 形对比从 0.10 降到 0.07（旧印片对比本来就低）。

### 底部横条：参考图的字缝其实是干净的

一度以为参考图"下半段字缝被猫身填满"，于是把 `--gutter-fill` 加到 0.36——结果下半幅糊成一块照片，CATS 只剩上半截可读。**把参考图底部横条裁出来放大看**才发现：字缝到基线都是深色，只有一只猫爪越过基线垂到留白里。`--gutter-fill 0.15` 只是让下沿略带连贯感，不是"填满"。

**教训**：判断"参考图某个区域是不是被填满"时，别用缩略图，裁那一条出来放大。缩略图上"看起来连着"的东西，放大往往是一条干净的缝。

## 十二、「字外也露一点」的四次翻车（第十轮）

用户的要求是"字母外面也可以适当加一些图，能直接看出是两只猫，保障画面完整"。参考图里字外露的是：橘猫一只前爪垂在字下、白猫的毛越过字右缘、字底还有极薄一条台面。

### 前三次：都想在字外放"一块照片"

| 做法 | 结果 | 为什么错 |
|---|---|---|
| 把逐列判定的门槛放宽（`max_cover` 0.34→0.46、`max_run` 0.18→0.32） | 抓出一块 465px 宽的横带，字被压在照片条上 | 那套判据是找"又窄又深的部件"的，放宽就等于允许整条边 |
| 沿单词外接框做矩形淡出（alpha 随距离线性衰减） | 字外一圈半透明亮晕 | 整段渐变 = 发光；照片延续应该是"实际像素 + 短过渡"，不是渐隐 |
| 只把矩形收窄到 3% 字高 | 字顶/字底各一条细照片线 | 往上补没有内容支撑，只会露出墙或天空，看着像套印没对准 |
| 补图加在投影之前 | 字下方多一条黑带，像照片断成两截 | 投影把补图当成"溢出主体"，在字外压了一层暗 |

### 第四次：把"地面线"对齐，而不是"加照片"

关键认识：参考图的立体感不是加出来的，是**对齐出来的**——字的下沿压在地面线上，身体在字里，爪子自然垂在字外。

- `_ground_row(alpha)`：逐行数主体宽度，从底边往上走，第一行"够宽"的就是地面线（再往下只剩爪/尾这种细东西）。没有明显地面线（< 4% 主体高度）就跳过。
- 计算方式：`s = max(bw/w, bh/h) * zoom`，`fy = (ground * s - box_h) / (nh - box_h)`，写回 focus。
- `_outer_fringe(sa, region, depth)`：只在**外接框之外**给一层软边遮罩，框内为 0（否则整块字被照片糊掉）；`soft = 0.45 * depth` 做短过渡，边缘不毛也不发光；横向两端按 12% 宽度收口，避免照片带齐刷刷断掉。
- 顺序：投影 → 补图 → 贴照片。补图不能进投影，也不能进 `photo_zone` 之前（会被当成溢出主体）。
- 方向默认只做**下方**：上方露出的该是耳朵这类"部件"，交给逐列判定。

### 参数落点

`--spill 0.14`（原 0.16）、`--extra 0.07`、`--gutter-fill 0.15`、`_profile_zone` 的 `max_cover 0.42 / max_run 0.26`。

回归：特写猫、草莓 LENS 都不会因为补图变脏——主体没有"落地线 + 细部件"时 `_ground_row` 返回 None，补图深度也小，肉眼几乎看不出，只是字下多了一点点照片。
