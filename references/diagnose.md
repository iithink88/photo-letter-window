# 诊断手册 · 看照片 → 填七槽 → 自检

## 一、看照片（内部完成，不输出给用户）

按顺序回答五个问题，答不上来就别开始写提示词：

1. **主体是什么？** 一个能用名词说清的东西。照片里同时有 3 个以上主体时，选占面积最大或最居中的那个，其余写进"环境"。
2. **主体落在画面哪一段？** 这是全流程最容易翻车的一问，见第二节。
3. **主体的视觉重心在哪？** 眼睛、鞋头、杯口、花瓣中心、人脸的鼻梁——照片带要出现的就是这里。
4. **主体的哪一块外轮廓最有辨识度？** 剪影测试：把它涂成全黑，还认得出吗？认得出 = 可以当突破元素。
5. **光线是什么？** 顺光/侧逆光/阴天散射/暖光。这个词既进照片描述，也决定底色用深还是用米白。

## 二、取景判断（决定成败，比选词更关键）

照片带取的是**照片里主体的那一段**。程序路径已经会自动做几件事，所以你只需要判断"能不能救"：

| 主体位置 | 结果 | 处理 |
|---|---|---|
| 占满画面上下（人全身、相机特写、猫横躺） | ✅ 完美 | 直接做，什么都不用调 |
| 集中在中间（半身、桌上一杯咖啡） | ✅ 自动处理 | 引擎按主体 bbox 反推缩放，把主体铺满带子（`--window-fill` 默认 0.75） |
| 主体很小、四周全是环境（远景人像、大场景里一个人） | ⚠️ 放大后会糊 | 先裁图再进流程，或 `--window-fill 0.8` 适当放宽 |
| 只在上半（天空占下半、站立人像的腿以下全是地面） | ❌ 会废 | **先裁图**：把照片裁成主体占中下部，再进流程 |

**判据**：只看照片带那一条——里面能不能认出主体？如果只认出"主体的一角"或"主体脚下的地面"，这张图就不合格。

> 这条是用户反馈后改的。原先只调取景位置不调缩放，结果躺在石台上的猫，窗里透出来的是猫头顶一截毛 + 下方整块石台 + 草地——现在引擎会按主体大小自动推镜头，还会把抠图带上来的地面切掉（详见 `SKILL.md` 的"四个自动判断"）。

示例图全部满足这条：猫横躺在中部、运动员双腿在下方、咖啡壶占满、相机特写没有背景。

## 三、选词法

**字数**：3-4 个字母最佳。示例 CATS(4) / RUN(3) / BREW(4) / ACE(3) / LENS(4)，没有一个是 5 个。

| 字母数 | 字高占画布（glyph / band 的下栏） | 结论 |
|---|---|---|
| 3 | 95%+ / 55-70% | **最佳**，字母顶天立地 |
| 4 | 90%+ / 45-60% | **最佳**，略有余地，参考图就是 4 个 |
| 5 | 75-85% / 35-45% | 偏矮，靠压缩和出血勉强撑住 |
| 6+ | <65% / <35% | 不要用，气势全无 |

> glyph 的字高能到 90%+ 是因为**画布按词长配的横构图**：4 个字母配 2:1，5 个字母就得配 2.4:1。硬塞进 3:4 竖版，前四档全部作废。

**字形**：多选带封闭腔（O、A、R、D、B、S）的词——镂空面积大，照片透得多。全 I/L/T 的词（如 TITLE）窗太小，照片透不出来。

**语义**：词要跟主体有张力，不是给东西贴标签。
- 差：猫 → CAT（等于什么都没说）
- 好：猫 → CATS（复数，像片名）
- 差：咖啡 → COFFEE
- 好：咖啡 → BREW / RITUAL
- 差：跑鞋 → SHOES
- 好：跑鞋 → RUN / PACE / STRIDE

**语种**：只能英文全大写。中文千万别用——图像模型渲中文必崩，字形一乱整个"窗"的概念就废了。

**自检句**：这个词读出来，像不像一部电影的名字？像 = 可以；像商品吊牌 = 换。

## 四、选色法（不许自己编）

```bash
"$PY" "$SK" analyze <图>
```

| 字段 | 用途 | 说明 |
|---|---|---|
| `suggest_bg_dark` | **深底方案** | 保留照片色相、压暗到 16% 明度，照片本身不暗时首选 |
| `suggest_bg_paper` | **米白方案** `#F2E8D5` | 照片偏暗、或想要 RUN/ACE 那种明快感时用 |
| `suggest_accent` | 标语/线条颜色 | 从这个色派生，别引入第三种色系 |

**规则**：
- 照片偏亮 → 深底（分界线才看得见）。
- 照片偏暗 → 米白底（否则整体糊成一团）。
- 深底就用浅色字（米白小字 + 亮色标语）；米白底就用深墨小字（`#1C1B19`）+ 亮色标语。

**为什么不用纯黑纯白**：#000000 / #FFFFFF 会让画面立刻有"数码感"，而整个版式的立身之本是"印刷品"。黑用带一点暖的深色，白用 `#F2E8D5`。

## 五、装饰三段（这是"像海报"和"像 PPT"的分水岭）

示例图的完成度几乎全靠这三段。缺任何一段，出来就是"一张图加几个大字"。

### ① 手写标语（必需）

- 位置：字母上方、靠右（CATS / BREW / LENS）或靠左（RUN）。
- 语气：**两个词**最稳。`Sunny Days` `Keep Going` `Slow Mornings` `Game On` `Shoot Film`。
- 颜色：强调色，与底色形成冷暖对比。
- 倾斜：-5 到 -10 度，手写感来自不水平。
- 中文可用在程序路径的 `--tag`（本地字体渲染不会崩）；AI 路径一律英文。

### ② 底部关键词行（必需）

两段，左右分置，极小的疏排大写字母：

| 位置 | 内容 | 示例 |
|---|---|---|
| 左下 | 三个词用斜杠分开，像索引 | `COFFEE / RITUAL / FOCUS` |
| 右下 | 一句短语，像题注 | `36 FRAMES PER STORY` |

字号是单词高度的 1/15 左右，字距拉到字宽的 1/4——疏排是"高级感"的直接来源。

### ③ 手绘线条（可选，但很值）

一条细的、不完美的曲线掠过字母表面，压在字母最上层。BREW 是绕字一圈的椭圆，ACE 是球的抛物线，RUN 是一条带箭头的斜线。

作用是打破"字母整整齐齐排在一条基线上"的呆板感，让画面有手作痕迹。

### ④ 小图标（可选）

猫爪印、光圈图标、跑步小人、太阳——放在角落，与主色同色系，尺寸很小。它们不承担信息，只承担"这是设计师做的"这个暗示。

## 六、突破元素判定

突破元素是"压过字母边界"的那个部件，必须满足两条：**在主体上能找到**、**轮廓简单**。

| 主体 | 突破元素 | 说明 |
|---|---|---|
| 猫 / 狗 | 耳朵尖、鼻尖、前爪 | 耳朵最好，形状有识别度 |
| 鞋 | 鞋头、鞋带结 | 鞋头压边最干净 |
| 手冲咖啡 | 壶嘴、杯口、握杯的手 | 手最容易出错，优先壶嘴 |
| 球类运动 | 球拍边缘、球体一半 | 球体压边最有张力 |
| 人像 | 头顶发际线、肩线、抬起的手 | 肩线最稳，手最容易崩 |
| 相机 / 物件 | 镜头筒、背带 | 镜头圆环压边很高级 |

**没有合适的突破元素怎么办**：程序路径直接让照片区块压过字母上沿（`--bite 0.05`），视觉上同样成立。AI 路径则宁可写"无"，也不要让模型硬编一个变形的手。

## 七、九条自检（交付前逐条过）

1. **字里是照片**：字母笔画内部是照片吗？字母以外是纯色吗？**反过来就全废**。
   **别靠眼睛判**——这个版面天生有图底反转错觉，字母够粗时深色字腔会被读成"实心黑字"。两条可靠办法：
   ① **裁一个字母放大看**（单裁 A 字）：两条斜腿是毛 = 对，三角内腔是深色 = 对；
   ② 量**照片覆盖率**（离底色超过阈值的像素占比）：参考图 **44–45%**，成片应落在 **40%±3**。掉到 33% 说明字太窄／字距太松，画面一眼显空；冲到 43% 以上要回看字腔还开着没有——覆盖率是可以靠"把字挤胖"刷出来的，但字腔一糊，字就没了。
2. **底色干净**：字母之外除了探出的那个部件，还有别的影像吗？底色出现第二层照片 = 字的边界没了。
2b. **主体完整**：字里能认出主体吗——整张脸、整只爪、整个鞋头？还是只剩一角毛、一块石头、一条地面？主体比字小时，说明镜头没推够。
3. **同源**：字母里跟上方照片对得上（同机位、同色调、同颗粒）？接缝看得出来吗？
4. **字号与字重**：单词左右各留 2–4% 余量，**glyph 字高 ≈ 0.60 画布高**（上留 0.20 放标语、下留 0.20 放垂下来的部件），band ≥45%。字腔是否还开着（A 的三角没被糊死、C 的碗还透光）？字母之间有没有一道细深色缝？——太细读成黑字，太粗读成一块照片；为了追覆盖率把字挤胖，最先死的就是字腔。
5. **探出**：把字母遮住，伸出来那部分还能独立认出来吗（一只爪、一只鞋、一个球拍）？有单向接触投影吗？有没有变成 3D 浮雕？
6. **边缘**：字母是照片硬切，还是被描了一圈白边/发了光/浮了雕？
7. **装饰**：手写标语在吗？底部两行小字在吗？有没有糊在一起？
8. **文字**：单词拼对了吗？有没有冒出汉字？标语有没有大到抢戏？
9. **质感**：整体像旧印刷品（有颗粒、略褪色、不完美），还是像渲染图（干净、发光、锐利）？

第 1、2、3 条任一不过 → 重出，别交付。这三条是这个效果的命门。
第 5 条不过 → 只是字母窗，没有前后层次，效果会平；但**宁可平也不要漏**——整条边渗出去比不探出更难看。

## 八、参数速查（程序路径）

| 项 | 值 | 备注 |
|---|---|---|
| 画布 | **glyph 1440×1000（1.44:1）**；band 1152×1536（3:4） | 实测参考图成片 529×368 = 1.44。竖版装不下四个满高字母，2:1 又会把上下留白压没 |
| 照片占比 | glyph 0（无上横条）；band 0.50 | 想更电影感可 0.54 |
| 压边量 | 0.03 | 只对 band 有效；> 0.08 会吃掉字顶 |
| 单词宽度 | glyph **0.96** / band 0.96 | 左右各留 2–4%。给到 0.907 时字会变窄、缝变宽，覆盖率塌到 33% |
| 压缩系数 | glyph 0.55 / band 0.72 | 0.55 必须配 `--fat-x 0.030`，否则竖笔画被压细 45% |
| 字重 | **glyph：`--weight-pct 0` + `--fat-x 0.030`** | Arial Black 本身够重，只需补横向。整体吹胖（`--weight-pct`）会把字腔糊死；`--fat-x` 一旦 >0.035，A 的三角和 C 的碗会被横向挤没——覆盖率好看但字读不出来 |
| 版面模式 | **glyph** | 底色 + 照片填满字母 + 主体渗出；`band` 照片带压字；`window` 纯字母窗 |
| 主体外扩 | **1.16** | `--subject-out`，必须 >1，否则主体的边就是字的边，永远伸不出来 |
| 字与带的明暗 | key=dark + veil 0.55 | 只压明度不压颜色，字里画面看得见；软限幅天花板=带均亮度×0.62；`veil 1` = 实心墨块 |
| 墨色 | 自动 | 深底=底色；浅底=同色相近黑 |
| 字高下限 | 0.52 | 不足自动放大，放不下时自动回退 |
| 窗框 | **0** | 示例图全部无描边，加框会变"贴纸感" |
| 标语字号 | 0.040 | 占画布宽，两个词最稳 |
| 底部小字 | 0.0135 | 很小，但字距要拉开 |
| 底部余量 | glyph **0.165** / band 0.10 | 实测参考图字底落在 0.80H。给到 0.218 图片覆盖率只剩 33% |
| **满窗** | **0.75**（band）/ 0.95（window 与 glyph 基准） | `--window-fill`，按主体大小自动推镜头；0=完整含住留背景，1=铺满。glyph 会再乘主体外扩 |
| 字高下限 | glyph **0.573** / band 0.52 | glyph 不要顶天立地：上留 0.209、下留 0.218 |
| 手动再拉近 | 1.0 | `--window-zoom` 叠加在自动对位之上，>1 更近 |
| **抠图溢出** | **glyph 0.14** / band 0.42 | 相对字高。要让整只爪子垂下来给 0.22–0.26。整片主体别用，改走 AI；整条边会自动关 |
| 字外补图 | **glyph 0.07** | `--extra`：照片从字数外缘再淡出一点，让身体/毛延到字外。0=关；>0.12 成照片带 |
| 字缝贯通 | **glyph 0.15** | `--gutter-fill`：字缝下段允许主体填进去的比例。0=整条字缝干净；>0.35 下半幅糊成一块照片，字读不出来；字腔永不受影响 |
| 做旧 | **glyph 0.75** | `--distress`：抬黑位＋暖光＋斑块＋颗粒，**并且咬字形轮廓**（0.007×字高）。只做照片不做字边，一眼是现代软件排的 |
| 投影强度 | 0.55 | 深色底上看不见是物理必然，别硬提 |
| 颗粒 | 0.55 | 0.3 干净，0.7 复古 |
| 暗角 | 0.18 | 0 太现代 |

**版面配平公式**（放不下时按这个顺序让）：
`下栏高 = 标语带 + 字高 + 底部余量`。三者打架时，先让字高，再让底部余量，最后才动标语——标语是装饰，字是主体。
